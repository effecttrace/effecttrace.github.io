Problem

The call is traced. The effect is not.

An agent calls a tool, and a trace shows the invocation. The consequences arrive later and elsewhere: the Kubernetes API accepts a mutation, a controller reconciles it asynchronously, ReplicaSets and Pods come and go, and latency or errors move.

Between "an action was requested" and "these effects followed" there is a gap that neither traces nor timestamps can close on their own.

Observation windows bound what can be attached. A signal change inside the window is only a correlation; one after it is not attached at all.

Traces stop at controllers

Controllers do not carry the original trace context. The span that requested a rollout ends long before the rollout does, and the Pods it produced never mention it.

Timestamps alone mislead

In a busy cluster something always changed in the last minute. "It happened after" is not "it was caused by", and a concurrent human change looks exactly like a controller reaction.

EffectTrace grades every edge

It never presents temporal correlation as causation, refuses to attach changes it cannot connect structurally, and says so when two actions compete for the same change.

How it works

From one tool call to an evidence-graded effect graph

One Go collector reads signals your platform already produces and composes them into a graph. Every edge records the rule that admitted it.

  1. Observe the action

    An MCP tools/call arrives as an OpenTelemetry span with W3C trace context carried in params._meta, or a human kubectl request appears in the audit log.

  2. Prove the mutation

    The instrumented client records the server-echoed Audit-ID, object UID and resourceVersion; the audit event confirms them independently. That is DIRECT evidence.

  3. Follow the controllers

    Owner references matched by UID lead from the Deployment to new ReplicaSets and Pods inside the reconciliation window, but only when no other action claims the change.

  4. Grade and explain

    Telemetry changes are attached as correlation only. Each node is graded by its weakest edge; ambiguous and excluded observations are listed, not hidden.

The pipeline: four inputs, one bounded and deterministic core, portable outputs.

A rollout restart, end to end: each object reached through the evidence that justifies it.

Evidence model

Five evidence classes, one rule

Each relationship admits exactly one evidence class, enforced by the data model, so timing can never be dressed up as direct or structural evidence.

A path is only as strong as its weakest edge

A node's grade is the weakest evidence on its strongest path from the action: ATTRIBUTED when every edge attributes, CORRELATED as soon as one edge is only temporal. Change the edges below to see the grade of the last node.

action request Deployment Pod

Grade of Pod: ATTRIBUTED Every edge on the path attributes.

Ambiguity: an honest "cannot tell"

A change inside the windows of two actions that both changed an owner of the object is recorded as an ambiguity with both candidates, and attributed to neither. EffectTrace prefers "cannot tell" to a confident wrong answer.

Exclusion: visible false-attribution protection

A nearby change without an ownership path, a change claimed by another action, or a signal of a workload outside the action's scope is listed as an exclusion with its reason. You can see what was noticed and why it is not part of the graph.

Architecture

One collector. Read-only, bounded, deterministic.

EffectTrace is a single Go collector plus a CLI. It is not a tracing backend, an MCP gateway, an AIOps engine or a model that guesses causality.

Sources

  • OTLP/HTTP trace receiver (POST /v1/traces)
  • kube-apiserver audit log tailer (JSON lines, rotation-aware)
  • Stripped client-go informers for workloads, Pods, Services and Events
  • Prometheus range queries for configured signals

Core

  • One bounded ingest queue with explicit backpressure (HTTP 503 with Retry-After)
  • Idempotent in-memory store with size and age limits
  • Correlation engine: actions, targets, windows, claimants, grades
  • Signal evaluator against a pre-action baseline

Outputs

  • Read-only HTTP API and the effecttrace CLI
  • Canonical JSON with a published schema
  • OTLP graph spans that link to the tool span
  • Prometheus /metrics and replayable recordings

Read-only RBAC

get/list/watch only. No mutation rights, never ConfigMaps or Secrets.

Bounded

Every queue and collection has a size and age limit. Producers see backpressure, not silent loss.

Deterministic replay

Graphs are rebuilt from stored observations: the same input in any order gives byte-identical canonical JSON.

Portable

A reusable client-go RoundTripper records Audit-ID and object identity without recording bodies.

effecttrace explain walks a graph in the terminal and ends every correlated answer with the same caveat.

Proof

Scored against ground truth, failures included

The experiment suite runs against a kind lab and scores every effect graph against ground truth derived from the harness's own actions and an independent watch of the cluster, never from EffectTrace output.

Quick start

A real lab on your laptop

Requirements: Go, kubectl, and Docker or Podman. No cloud account, model API key or SaaS backend is needed. The lab writes its own kubeconfig and never touches your current context.

make demo-run is real end to end: a scripted MCP client calls a Go MCP server, a human scales another workload at the same moment, and two agents act concurrently on two workloads.

Full quick start on GitHub →

$ git clone https://github.com/effecttrace/effecttrace && cd effecttrace
$ make demo-up # kind lab: shop workload, OTel Collector, Prometheus, EffectTrace
$ make demo-run # a scripted agent acts; EffectTrace explains each graph
$ make demo-down # deletes only the effecttrace-lab cluster
