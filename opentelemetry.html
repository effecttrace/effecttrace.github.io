Integrations · OpenTelemetry

OTLP in. Span links out.

EffectTrace consumes the traces you already emit and exports what it learned back to your tracing backend, without pretending that a computed graph is part of the original trace.

OTLP/HTTP receiver

  • POST /v1/traces, protobuf or JSON, optionally gzip-compressed.
  • A relevance filter and an attribute allowlist drop everything EffectTrace does not need before it is stored.
  • When the bounded queue is full the receiver answers HTTP 503 with Retry-After; producers see backpressure instead of silent loss.
  • Typical deployment: your OpenTelemetry Collector fans traces out to your backend and to EffectTrace.

What a tool call looks like on the wire

MCP clientSends tools/call with W3C traceparent in params._meta.
MCP serverContinues the trace: a server span for the tool, named by mcp.method.name and gen_ai.tool.name.
client-gopkg/k8sinstrument creates a child span per mutating request with effecttrace.k8s.* attributes and the server-echoed Audit-ID.
EffectTraceLinks tool span → client span as TRACE_LINK (parent/child, at most 32 hops) and request → object as DIRECT.

MCP trace context propagation

MCP has no transport-level headers that survive every transport, so trace context travels inside the request: the W3C traceparent (and tracestate) are carried in params._meta of tools/call. The demo uses the official Go MCP SDK for both the tool server and the scripted client.

Missing context degrades, it does not guess. If a tool call carries no trace context, a request made during the tool span can only be attached by timing, and everything below it is graded CORRELATED in that graph.

// tools/call request (abridged)
{ "jsonrpc": "2.0", "method": "tools/call",
  "params": { "name": "restart_workload",
    "arguments": { … },
    "_meta": { "traceparent": "00-<trace-id>-<span-id>-01" } } }

Graph export as span links, not children

An effect graph is computed after the fact, across many asynchronous observations. Reporting it as a child of the tool span would claim a causal call relationship that never existed. Each completed graph is exported as a new root span, effecttrace effect_graph, that carries a span link to the initiating tool span with effecttrace.link.type = initiating_action.

  • The span covers the action start to the end of its last observation window.
  • Each edge becomes a span event effecttrace.edge with relationship, evidence, endpoints and reason.
  • Edge counts per evidence class are span attributes, so a backend can query "graphs with temporal-only edges".
  • Only COMPLETE graphs are exported.

Attributes in the effecttrace.* namespace

  • effecttrace.graph.id · effecttrace.graph.status
  • effecttrace.action.id · effecttrace.action.kind
  • effecttrace.edge.relationship · effecttrace.evidence.type
  • effecttrace.edge.from · effecttrace.edge.to · effecttrace.edge.reason
  • effecttrace.node.type · effecttrace.k8s.uid
  • effecttrace.edges.<evidence> counts
  • effecttrace.k8s.audit_id · effecttrace.k8s.verb (client spans)
  • effecttrace.k8s.object.uid · …resource_version
