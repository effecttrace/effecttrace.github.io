Metadata, not payloads

EffectTrace is an observability system, not an authorization system: its graphs are evidence for people, not inputs to security decisions.

Data minimization

  • Kept: kind, namespace, name, UID, verb, timestamps, trace and span IDs, tool name.
  • Never stored: prompts, tool arguments and results, request bodies, Secret and ConfigMap contents, tokens.
  • Human usernames are pseudonymized with a keyed hash.
  • The lab audit policy never goes above Metadata.
  • Objects are stripped by an informer transform before they reach the cache.

Threat-model highlights

The full analysis lives in the threat model on GitHub. These are the decisions that shape the design.

Least privilege

The collector has read-only RBAC (get/list/watch) and holds no mutation rights. It is separate from the demo actor's narrowly scoped permissions.

Forged telemetry

A client span alone cannot fake an audit match: the audit event is used only when verb, resource, namespace and name agree. Client-chosen Audit-IDs are never trusted.

Hostile or noisy input

An attribute allowlist, input validation and bounded queues and stores limit what an untrusted producer can do. Overload produces 503 backpressure, not unbounded memory.

No sensitive kinds

ConfigMaps and Secrets are never watched. Request and response bodies are never recorded, including by the client instrumentation.

Read-only interfaces

The HTTP API is read-only. Graphs and exported spans contain identifiers and reasons, not payloads.

Not an authorization system

Do not gate deployments or access on a graph. Evidence can be incomplete when sources are missing, and a graph says so through coverage, not through confidence.

Report vulnerabilities privately as described in SECURITY.md. Read the privacy and threat model documents.
